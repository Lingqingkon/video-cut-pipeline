# video-cut-pipeline

一条从**客户文稿**到**剪映草稿工程**的短视频自动剪辑流水线。

输入一份文案，输出一个可以直接在剪映里打开、字幕和音效都已经挂好的草稿工程。中间涉及素材检索、AI 视频生成、语音对齐、超分、画面文字清除，全部由脚本 + 模型 + MCP 工具链协作完成，每一步的产物都落盘，可以单独重跑。

> 这不是一个 fork，是从零搭的。核心脚本 `vcp`（23 个模块）和 5 个 MCP 服务都在这个仓库里。

---

## 它解决什么问题

短视频代做这件事，手工流程是这样的：读文案 → 想要几个镜头 → 去素材网站翻 → 下载 → 拖进剪映 → 对齐口播 → 一句句打字幕 → 给重点句加动画和音效。

其中**创意部分**（理解文案、设计镜头）只占一小部分，**剩下全是确定性的机械劳动**，而且每次都一样。

这条流水线做的事情就是把机械劳动全部脚本化，把创意部分留给模型：

- 确定性的活（检索、下载、裁切、抽音轨、切段、排轨、写草稿）→ **脚本**
- 判断性的活（理解文案、设计镜头表、识别人设）→ **模型**
- 重 GPU 的活（生成、超分、重绘）→ **远端算力**

一条判据贯穿全仓库：**每一段的产物必须落盘，且能从上一段产物单独重跑**。改一个镜头的字幕不该让整条片子重新生成。

**技术栈分工**

| 层 | 是什么 | 干什么 |
|---|---|---|
| 调度 | Agent（LLM）+ 技能说明 | 编排、写镜头表、调工具 |
| 工具 | 5 个 MCP 服务 | 写剪映草稿、驱动 Photoshop / Blender、读图 |
| 脚本 | `vcp`（Python，23 模块 / 14 命令） | 全部确定性步骤 |
| 生成 | ComfyUI + MiniMax-H3（远端 GPU） | 生人设图、生视频（音视频联合） |
| 后处理 | ComfyUI + Real-ESRGAN / VSR | 超分、清除画面烧字 |
| 出口 | 剪映专业版 | 打开草稿、人工导出 |

## 五段骨架

| 段 | 做什么 | 命令 |
|---|---|---|
| 1 | 文稿 → 元素提取 → 镜头表（**成本闸门**） | 模型现做，不脚本化 |
| 2a | 混剪：Pexels / Mixkit 检索下载 + 裁切规格化 | `vcp stock` |
| 2a' | 口播：实拍素材入库（保音轨、不截时长） | `vcp footage` |
| 2b | AIGC：镜头表 → 生成 | `vcp charset` → `vcp generate` |
| 2.5 | 超分 480×864 → 1080×1920 | `vcp upscale` |
| 2.7 | 去烧字：抹掉模型烧进画面的文字 | `vcp desub` |
| 3 | 抽音轨 + ASR 逐字时间戳 + 与台词比对 | `vcp align` |
| 3.5 | 重点句解析 + 切音频段 | `vcp keyphrase` |
| 4 | 排轨生成 manifest | `vcp manifest` |
| 5 | 落剪映草稿：字幕 / 动画 / 音效 | 剪映 MCP `build_draft` |

命令细节见 [`docs/04-cli-reference.md`](docs/04-cli-reference.md)。

## 几条硬纪律

这些不是"最佳实践"，是踩过坑之后写死的规则。

**成本闸门。** `vcp generate` 默认 **dry-run**，只打印将要生成的清单，必须显式加 `--yes` 才提交。生视频慢且计费——实测 124 帧约 71 秒，一个 7 镜头项目吃掉约 10 分钟 GPU。镜头表必须落盘、给人看过。

**AI 生成的台词必须比对，不能默认它念对了。** MiniMax-H3 是音视频联合生成，口型由模型原生出，但它**是否一字不差念出给定文本不可靠**。第 3 段的 ASR 结果要与镜头表里的 `text` 逐字比对，不一致就**非零退出**（退出码 `2`）——刻意用非零，就是为了不让"AI 念错了台词"被静默跳过。

**超分开关和画布尺寸是一对。** `upscale.enabled` 与 `jianying.canvas` 必须同时改，只改一个会出现"超分了但画布还是 480"或"画布 1080 但素材还是 480"的半套状态。选哪个文件由 `artifacts.resolved_clip()` 统一决定，禁止直接读 `shot["file"]`。

**超分产物写 `clips_sr/`，绝不覆盖 `clips/`。** 去烧字写 `clips_clean/`，同理。换模型或调参数要能只重跑那一段。

**音频效果只能挂在音频段上。** 要让重点句单独有音效，必须先把音频按句切成独立段——所以顺序是 **对齐 → 切音轨 → 挂效果**，对齐是音效的前置条件。

**字幕统一写成独立 text 段，不用 `srt_import`。** `srt_import` 的 style 是整份文件级的，不能逐句设动画；text 段的 style 是段级的，能力是它的超集。

**终点是草稿工程，不是成片。** 剪映 MCP 不负责导出，最后一步由人在剪映里点。

## 几个真正的硬仗

完整的踩坑记录在 [`docs/05-hard-problems.md`](docs/05-hard-problems.md)，这里挑三个：

**模型会把台词烧进画面。** MiniMax-H3 有时把台词直接渲染成画面内文字（实测约 7 条里 2 条中招），和剪映里加的字幕叠成两份字，而**烧进去的删不掉**——它在像素里。

试过两条死路：提示词里明确写"不要出现任何文字"，照样烧；裁边也不可行，实测烧字位置不固定（一条在 73% 高度、一条在 80%），要裁掉得裁画面 40% 高度。

最终方案是**检测 + 重绘**：抽帧量化"边缘最密带"的文字笔画密度，阈值 `0.14` 在 13 条标注样本上零错判；检出的镜头走云端 VSR 的 `sttn-det` 模型挖掉 mask 区域重绘，**文字笔画像素 1589 → 0，音轨用 `-codec copy` 原样合回所以时间基准不变**。

顺带一个反直觉的结论：`sttn-auto` 抹不掉字。那个模型输入是 3 通道、没有 mask，指望它自己"学会"擦字，实测 1589 → 1589，等于没做。

**ASR 不能直接强制对齐。** 直觉做法是把已知文本强制对齐到音频上，但那样会把时间戳**硬摊到给定文本**——模型念错了你也看不出来。所以先做 ASR 识别实际说了什么，再与原文本比对。

比对也不能用整体相似度：ASR 在环境音段落会幻觉出字符，把整体相似度严重拉低，而真正的念错会影响**覆盖率**。所以判定用 coverage，不一致率超过 `0.15` 就报错。

**远端实例的地址每次开机都会变。** 云 GPU 实例关机后原地址立即失效，开机后端口也会变。所以 `vcp` 自己开 SSH 隧道（paramiko），不依赖外部 `ssh -L`，也不依赖实例的公网端口配置——换机器不用改盒子配置。

还有一个坑值得单独说：远端 ComfyUI 启动时 `< /dev/null` 不能省。只重定向 stdout/stderr 的话，后台进程仍持有 stdin，远端 channel 永不关闭，脚本读输出必然超时。

## 实测数据

都是真机跑出来的，不是理论值。

| 项 | 数值 |
|---|---|
| 生成分辨率 / 帧率 | 480×864 @24fps（0.4MP，5:9） |
| 采样 | steps 8、cfg 1.0 |
| 生成耗时 | 124 帧 ≈ 71 秒；158 帧 ≈ 90 秒；7 镜头项目 ≈ 10 分钟 GPU |
| 超分耗时 | 480×864 → 1080×1920，124 帧 ≈ 126 秒（约 24 倍实时） |
| 烧字检测 | 干净画面 score 0.012~0.021，烧字 0.147~0.148，阈值 0.14 落在两簇中间 |
| 去烧字效果 | 文字笔画白像素 1589 → 0，音轨 `-codec copy` 不变 |
| 检测器验证 | 13 条标注样本（5 正 8 负）零错判 |
| 听检阈值 | 覆盖率不一致率 > 0.15 判为念错 |

## 快速开始

这个系统依赖的东西比较多（剪映、ComfyUI、ffmpeg、Whisper 模型、显卡），完整步骤见 [`docs/06-setup.md`](docs/06-setup.md)。最小验证路径：

```powershell
cd scripts
python -m venv .venv
.venv\Scripts\python.exe -m pip install -r ..\requirements.txt

# 建一个项目
.venv\Scripts\python.exe -m vcp init demo --work-root D:\work

# 看 CLI 有哪些命令
.venv\Scripts\python.exe -m vcp --help
```

`vcp` 大部分命令需要一个已有的项目目录和 `config.yaml`。想看某条命令会做什么而不真的执行，多数命令支持先跑一次看输出——`generate` 默认就是 dry-run。

## 已知限制

诚实交代，这些还没做：

1. **导出环节没有自动化。** 剪映没有可用的导出接口，成片由人在剪映里点。流程终点是草稿工程。
2. **重点句靠手写或模型写。** `keyphrases.json` 目前由模型产出，没有自动识别关键词（优惠 / 福利 / 限时等）的兜底扫描。
3. **人设图链路和视频生成链路不在同一个后端。** 人设图用的 Krea2 权重只在本地 ComfyUI 上，视频生成在远端实例上，`comfyenv` 一次只开一个后端，混合模式还没做。
4. **文稿到镜头表这一步刻意不脚本化。** 一稿一议，固化模板反而限制表达。每次把 `shots.json` 存档就够了。
5. **剪映版本敏感。** MCP 是在 `10.0.5` 上验证的，新版本上动画 / 滤镜 / 在线资源的行为可能不同，改这些之后必须肉眼确认一次。

## 环境要求

- **Windows**（剪映只有 Windows / macOS 版，Linux 上整条草稿写入环节不成立）
- Python 3.10+（脚本层独立 venv，**不要**装进 ComfyUI 的环境）
- ffmpeg / ffprobe（规格化、抽音轨、抽帧）
- 剪映专业版
- ComfyUI（本机或远端）+ MiniMax-H3 权重
- CTranslate2 格式的 Whisper 模型（ASR 用，**不是** PyTorch 格式）
