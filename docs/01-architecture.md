# 架构与产物规范

## 三种任务型，一套骨架

三种视频类型只有"素材怎么来"这一段不同，其余完全共用：

| 类型 | 素材来源 | 特点 |
|---|---|---|
| **混剪** | 网络检索现成素材切片 | 丢音轨，当 B-roll，旁白压在上面 |
| **口播** | 真人实拍素材 | **保音轨**（人声就是内容），不截时长 |
| **AIGC** | 先生成人设图，再据其生成视频 | 音视频联合生成，口型原生 |

混剪和口播在音频处理上是**相反**的：混剪默认 `ffmpeg -c copy -an` 去音轨、时长截到镜头需要的长度；口播保留音轨、不截时长（视频才是时间基准）。

---

## 五段骨架

```
1. 文稿 → 元素提取 → 镜头表 shots.json          ← 成本闸门，必须人工确认
2. 素材获取（按类型分支）
     混剪 → vcp stock      检索下载 + 裁切规格化
     口播 → vcp footage    实拍入库，保音轨、核对时长
     AIGC → vcp charset 出人设图 → vcp generate 生成（t2v / r2v 自动选）
2.5 超分 → vcp upscale → clips_sr/
2.7 去烧字 → vcp desub → clips_clean/
3. 音轨 → vcp align → ASR 逐字时间戳 → 与台词比对      ← 听检
3.5 重点句 → vcp keyphrase → 解析时间 + 切音频段
4. 落草稿 → vcp manifest → 剪映 MCP build_draft
5. 字幕全 text 段；重点句拆成独立段挂 text 动画；重点句音频段挂声音效果
```

**每一段都必须能从上一段产物单独重跑。** 这不是口号，是整个目录结构的设计目标——尤其是 AIGC 那段，生视频耗时且计费，改一个字不能让整条片子重新生成。

## 项目目录

```
<work_root>/<project-id>/
├── config.yaml          本项目的配置（从 config.example.yaml 复制）
├── script.md            原始文稿，客户给的，只读不改
├── shots.json           ★ 镜头表 —— 成本闸门，人工确认后才进入素材获取
├── gen/                 生成侧原始输出（ComfyUI 直接落的，保留不动）
├── clips/               实际使用的片段（生成侧原始分辨率，480×864）
├── clips_sr/            超分后的片段（画布分辨率，1080×1920）
├── clips_clean/         去过烧字的片段（分辨率同 clips/，只抹掉画面里的字）
├── upscale.json         超分报告（每条的分辨率变化、耗时、来源文件）
├── desub.json           去烧字报告（mask 坐标、前后分数、前后白像素、帧数变化）
├── audio/
│   ├── <shot-id>.wav        交付用音轨（保持源采样率/声道）
│   ├── <shot-id>_s<k>.wav   按句切出的独立音频段（挂音效用）
│   └── _asr/<shot-id>.wav   ASR 专用，16k 单声道
├── assets/
│   └── char_<角色id>_sheet.png  人设图（多视图）
├── align/<shot-id>.json ★ ASR 逐字时间戳 + 与台词比对结果
├── subtitles.srt        普通字幕（已排除重点句）
├── keyphrases.json      ★ 重点句清单（独立动画 + 音效配置 + 对应音频段）
├── manifest.json        剪映 build_draft 的输入
└── preview/             抽帧、接触印相、预览图
```

★ 标记的是**契约**，字段不许各环节自己另起一套。

### 三条关于产物的纪律

**`clips_sr/` 是后期产物，绝不能覆盖 `clips/`。** 超分是可以重跑的步骤——换模型、调目标分辨率、改裁切方式，都要能只重跑这一段。源头片段必须一直留着，否则每次调参都得重新生成视频。`clips_clean/` 同理。

**分辨率不是恒等式，要实测。** 生成侧写的是 480×864，但真正落盘的时长以 ffprobe 为准（manifest 里的 `6.584s` 是量出来的，不是 `158/24` 算出来的）。超分同理：产物分辨率必须 ffprobe 实测等于目标，否则"跑成功"可能只是拿到了输入原片的回显。

**`audio/_asr/` 不是交付物。** ASR 要 16k 单声道，交付音轨要保持原始采样率和声道。两者必须分开——拿 16k 单声道覆盖 `audio/<shot-id>.wav` 会把成片音质悄悄降下来，而且那个路径正是剪映音频段和重点句音效指向的地方。

## 用哪个片段：`resolved_clip()` 是唯一判定

`clips/` 存生成侧原始分辨率（480×864，5:9），`clips_sr/` 存超分后（1080×1920，9:16）。

**后期一律调 `artifacts.resolved_clip(project_dir, shot, cfg)`，不要直接读 `shot["file"]`。**

规则（按顺序取第一个命中的）：

| 优先级 | 条件 | 用哪个 |
|---|---|---|
| 1 | `upscale.enabled` 且 `clips_sr/<id>.mp4` 存在 | `clips_sr/<id>.mp4` |
| 2 | `desub.enabled` 且 `clips_clean/<id>.mp4` 存在 | `clips_clean/<id>.mp4` |
| 3 | 其它 | `clips/<id>.mp4` |

做成开关而不是手工换文件，是为了避免**半套状态**：一半镜头处理过了、一半没有，而 manifest 里分不出来。

两个开关同时打开时，正确顺序是**先去字再超分**（超分跑在 `clips_clean/` 上）——否则超分会把烧进去的字一起放大。

**画布尺寸和 `upscale.enabled` 是一对，只改一个就会出现两种坏状态**：超分了但画布还是 480，或者画布 1080 但素材还是 480。

## 设计原则

**确定性的事走脚本，创意的事走模型。** 检索、裁切、抽音轨、切段、排轨、写草稿——都是脚本。理解文案、设计镜头表、识别人设——是模型。这条线划歪任何一边都会出问题：让模型做确定性的事会不稳定，让脚本做判断性的事会僵死。

**产物落盘是唯一的跨环节接口。** 不让脚本之间靠内存或管道传递数据，一律落盘。好处是任何一段崩了都能单独重跑，坏处是磁盘占用大——这个取舍在"生视频要花钱"面前不成立，落盘完胜。

**契约字段集中定义。** 镜头表、对齐结果、重点句清单、manifest 的字段各只有一处定义，各环节引用而不是各写一份。

**能报错就不要静默。** 听检不一致非零退出（退出码 2）、烧字检出可疑非零退出、帧数异常记 error。宁可中断，也不要把问题流到客户手里。
