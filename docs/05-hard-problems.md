# 踩过的坑与解法

这一篇是整份文档里最值得看的部分。每条都按 **现象 → 试过什么 → 为什么不行 → 最终方案** 写，失败的路径也保留——它们比成功的方案更能说明问题边界在哪。

---

## 1. 模型会把台词烧进画面

**现象。** MiniMax-H3 是音视频联合生成，口型由模型原生出。但它有时会把**台词直接渲染成画面内的文字**（实测约 25% 的镜头中招）。这和我们在剪映里加的字幕叠成两份字，而**烧进去的那套删不掉**——它在像素里，不是字幕层。

### 试过的两条死路

**提示词压制——无效。** 在 `generation.prompt_suffix` 里明确写了"画面中不出现任何文字、字幕、标题、水印、logo 或图形叠加"，模型照样烧。实测 7 条里 2 条中招。而且 `MiniMaxH3Director` 没有 negative 输入，没法用负向提示词压制。

即便如此，这段词缀**仍然由生成器无条件附加**——漏一次就出一条带双份字幕的片子，不能指望每次都记得写。它是"让这件事至少每次都做到"，不是"已经解决了问题"。

**裁边——断的。** 实测烧字位置不固定：73% 高度、80% 高度都出现过，还有既有素材在 70%。要裁掉得裁画面 **40% 高度**，不可接受。

### 最终方案：检测 + 重绘

**检测。** 抽帧后量化"边缘最密带"里的文字笔画密度，得到一个 score：

| 类别 | score |
|---|---|
| 干净画面 | 0.012 ~ 0.021 |
| 烧字 | 0.147 ~ 0.148 |

阈值取 **0.14**，正好落在两簇中间。检测器在 13 条标注样本（5 正 8 负）上**零错判**。

**阈值刻意取低。** 误报的代价是多跑一次生成（约 90 秒），漏报的代价是双份字幕到客户手里。这两个代价不对称，所以宁低勿高。

**重绘。** 检出的镜头走云端 VSR 的 `sttn-det` 模型，把 mask 区域挖掉重绘：

```
clips/<id>.mp4  →（VSR sttn-det）→  clips_clean/<id>.mp4
```

实测文字笔画白像素 **1589 → 0**。音频用 `-codec copy` 原样合回，所以时间基准不变。

### 反直觉的结论：`sttn-auto` 抹不掉字

VSR 有两个模型。`sttn-auto` 听起来更"智能"（自动检测要抹哪里），但它**抹不掉字**：那个模型的输入是 3 通道、**没有 mask**，指望它自己"学会"擦字，实测同一块区域 1589 → 1589，等于没做。

**必须用 `sttn-det`**，自己把 mask 传进去。

### 另一个反直觉的结论：`locate` 不要改成 auto

mask 的定位方式默认是 `bottom`——只让 OCR 在下半屏找字（烧字是字幕，只出现在下半部分）。

看着 `auto`（扫整帧）更通用，但**实测会毁画面**：VSR 的 PaddleOCR 把说书人的眼睛、鼻梁认成了文字，STTN 把那 62 行挖掉重绘，**脸被抹平了**。实测 5 条坏 3 条，改动集中在 17%~65% 高度的人脸区。

更麻烦的是**复检拦不住**：脸被抹平后那条带子更"干净"，score 只会更低。所以这类损坏不会触发任何告警。

## 2. ASR 不能直接强制对齐

**现象。** 需要把字幕对齐到语音。直觉做法是：已知台词文本，把它强制对齐到音频上。

**为什么不行。** 强制对齐会把时间戳**硬摊到给定文本**上——模型念错了、念漏了你完全看不出来，因为对齐算法假设文本是对的。

**最终方案。** 先 ASR 识别实际说了什么，再与镜头表里的 `text` 逐字比对。

比对也不能用整体相似度：**ASR 在环境音段落会幻觉出字符**，那些插入的字符会把整体相似度严重拉低，而真正的念错几乎不影响整体相似度（它只影响覆盖率）。

所以判定用 **coverage（覆盖率）**，不一致率超过 `0.15` 就报错，并且**非零退出（退出码 2）**。

**为什么退出码要是 2 而不是 1。** 因为 1 是"出错了"，2 是"跑通了但内容不对"。排轨逻辑对这两者的处理不同：1 应该修 bug，2 应该拿去问人。

## 3. 帧数量化：绝不能记成 error

**现象。** 请求 124 帧，视频出来是 141 帧。

**原因。** 这是 MiniMax-H3 的固定行为——帧数会被抬到固定档位上，档位等差 17 帧：

```
124 / 141 / 158 / 175 / 192 / 209 / 226 / 243
```

请求值一律抬到不小于它的那一档。

**为什么必须处理而不是放过。** 排轨用的是 `shots.json` 里的时长，视频实际长度对不上会让整条时间轴错位。表现是"**后面所有镜头都对不齐**"——很难反查到根源是帧数量化。

**处理方式。** 按实测把 `shots.json` 的 `duration` 改正。口径和 `vcp footage` 一致：**视频说了算，镜头表反过来对齐它**。

**踩过的坑：不能把量化记成 error。** 曾经把量化记为 error，结果连带把烧字重试循环短路掉了：

```python
if r.get("error") or r.get("skipped") or not suspect:
    break
```

实测开了 `retry_on_text: 2`，却一次都没重试过。**这个 bug 修过一次，别再犯。**

## 4. 超分：5:9 不是 9:16

**现象。** 生成侧配置写的是 480×864，看起来是 9:16。

**实际不是。** 480×864 = **5:9（0.5556）**，而 9:16 是 0.5625。差 **1.25%**。

原因：ResolutionSelector 按 32 的整数倍取值，宽度落在 480 而不是 486。

**所以放大到 1080×1920 时：**

- ❌ **不要拉伸** —— 会有 1.25% 的形变
- ❌ **不要留黑边**
- ✅ **`ImageScale` 的 `crop: "center"`** —— 先按比例放大填满目标框，再居中裁切

链路：`RealESRGAN_x4plus` 出 4×（1920×3456）→ `ImageScale(crop=center, 1080×1920)`。

**验收必须实测分辨率。** 如果输出显示 `480x864 -> 480x864`，说明挑到了输入文件而不是产物——"跑成功"是假象。

## 5. 音频效果只能挂音频段上

**现象。** 想让重点句单独有音效。

**约束。** 剪映的效果只能挂在**音频段**上，不能挂在时间点上。

**所以顺序是死的：对齐 → 切音轨 → 挂效果。** 对齐是音效的**前置条件**——不知道句子在哪里结束，就没法切段，就没法挂效果。

切出来的段落在 `audio/<shot-id>_s<k>.wav`，与交付音轨分开存。

**另一个约束**：首版**不支持音量关键帧**，只有整体 `volume` + `fade`。

## 6. 字幕用独立 text 段，不用 srt_import

**现象。** 需要给重点句加逐句动画。

**为什么不能用 `srt_import`。** `srt_import` 的 `style` 是**整份文件级**的，不能逐句设动画。

text 段的 style 是**段级**的，能力是它的超集（style / border / background / shadow / animations / keyframes 全都有）。

**做法。** 每条字幕 = 一个 text 段。重点句只是**多挂一个 `animations`**（`text_intro` / `text_outro` / `text_loop`），不需要"从 SRT 里排除"这类去重逻辑。

**唯一例外**：整条片子不需要任何逐句动画，而且手上已经有现成的 SRT——这时候才用 `srt_import`。

## 7. 视频段必须首尾严格相接

见 [`04-cli-reference.md`](04-cli-reference.md#时间轴段必须首尾严格相接)。核心是：**用端点差算时长**，而不是分别四舍五入 `start` 和 `duration`。

剪映的 `build_draft` 对重叠零容忍，实测直接报 `SegmentOverlap`。

## 8. 远端后台进程持有 stdin

**现象。** 远端启动 ComfyUI 的命令发出去了，日志也写了，但读输出一直超时。

**原因。** 只重定向 stdout/stderr 的话，后台进程**仍然持有 stdin**，远端 SSH channel 永不关闭。

**解法。** 启动命令末尾必须加 `< /dev/null`：

```bash
setsid nohup python main.py --listen 0.0.0.0 --port 6006 \
  > log 2>&1 < /dev/null &
```

这个坑的现象很像网络问题，容易误判。

## 9. 半套状态：一半处理过、一半没有

**现象。** 超分或去烧字跑到一半失败，`clips/` 和 `clips_sr/` 里各有一些片段。manifest 生成时看不出来哪些用了哪个版本。

**解法。** 后期一律调 `artifacts.resolved_clip(project_dir, shot, cfg)`，由它按开关和文件存在性统一决定，**禁止直接读 `shot["file"]`**。

这样"半套状态"最多表现为"有些镜头用了旧版本"，而不会表现为"manifest 里分不出来"。

配套的：`upscale.enabled` 与 `jianying.canvas` 必须同时改——它们是一对开关，只改一个就会出现"超分了但画布还是 480"或"画布 1080 但素材还是 480"。

## 10. 端到端各环节的失败代价不对称

几个阈值和设计的取舍都来自同一个判断：**两个方向的失败代价不一样**。

| 场景 | 这一个方向 | 另一个方向 | 选择 |
|---|---|---|---|
| 烧字检测阈值 | 误报 = 多跑 90 秒生成 | 漏报 = 双份字幕到客户手里 | 阈值取低（0.14） |
| 生成放行 | 多花 10 分钟 GPU 确认 | 生成错了全部重来 | 默认 dry-run，人工确认 |
| 听检不一致 | 停下来问人 | 台词念错流到成片 | 非零退出 |
| 去烧字复检不过 | 删掉产物重跑 | 坏产物被当好产物用 | 直接删 |

代价不对称的时候，**取保守的那一侧**。
